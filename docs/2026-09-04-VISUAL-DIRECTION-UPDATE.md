# 从“组件堆砌”到有辨识度的 Material UI

调研与本地实施日期：2026-09-04。本文区分官方依据、对截图的观察和本项目设计决策。未修改已有 Figma 文件，未提交或推送。

## 1. 我的判断

你提供的截图右侧不是一张普通业务页面，而是多个产品画面的展示组合。可见的特点包括主导画面的文字、明显的大小对比、内容图像、留白、不同形状及颜色重点。不能仅凭截图确认各示例的具体字体，也不能把展示外框、拼贴裁切当成真实应用的布局规则。

要借鉴的是“信息有主次、内容有表现、视觉语言一致”，而不是把每个页面都变成大字号、鲜艳底色和异形按钮。

Google 对 Expressive 的解释强调通过色彩、大小、形状、动效和内容分组引导注意力。设计团队也明确说明，表达可以安静，也可以强烈。[研究说明](https://design.google/library/expressive-material-design-google-research)、[设计团队访谈](https://design.google/library/design-notes-material-3-expressive-liam-spradlin)

## 2. 原 Skill 为什么容易生成组件堆砌

这是对本地指令结构的判断，不是对所有模型的普遍结论：

- 先建立完整 Token 和组件体系，再铺页面，容易把“完成组件清单”当成设计目标。
- 主题、密度、圆角虽然会询问，但缺少一段具体的视觉构想：这个产品最重要的是什么，什么应该醒目，什么应该安静。
- 默认排版强调基线角色，容易忽略 Material 允许的编辑式视觉重点。
- 图标规则主要解决“不能用占位黑点”，尚未完整描述项目级的风格、笔画、状态和字体协调。
- 流程和验收条款很多，但缺少实际运行的检查和稳定复现失败的测试。

## 3. 已落实的设计流程修改

现在的主线是：

    理解产品任务与原型
      → 形成视觉构想与注意力顺序
      → 建立少量主题、字体、图标样本
      → 做一张真实内容的代表页面
      → 产品确认，或按明确授权代选
      → 扩展组件、完整页面、状态与适配
      → 结构检查、视觉审阅、交接校验

代表页不是几张色卡：需要含真实中文、数字、关键动作和内容密集区域。方向明确只做一版；不明确才提供有实际差异的方案。已有批准体系可以直接继承，局部细调不需要重新走一轮品牌问卷。

新的视觉构想包括：

- 页面第一、第二、第三注意力对象。
- 哪些内容使用卡片，哪些使用行、共享背景、分隔和留白。
- 品牌高亮色的使用位置与中性区域。
- 字体角色与图标粗细的协调。
- 图像的主题、来源、裁切和用途；没有用途不强塞装饰图。
- 可以重复使用的品牌特征，例如数据排版、时间线、内容封面或适当的动效。

这些是设计判断，不冒充 Material 强制条款，也不要求每屏都有“主视觉大图”。

## 4. 图标：可以因项目不同，不必每个项目都换

官方 Material Symbols 提供 Outlined、Rounded、Sharp，并支持 fill、weight、grade、optical size 调整。因此，不同产品可以选择不同的视觉风格，同时保持 Material 的清晰度和一致性要求。[图标概览](https://m3.material.io/styles/icons/overview)、[Symbols 指南](https://developers.google.com/fonts/docs/material_symbols)

本次新增的项目级图标方案记录：

- 家族、来源与版本。
- 字重、视觉粗细、光学尺寸及默认填充。
- 选中/未选中状态政策。
- 与文字的视觉重量关系。
- 语义名称、源资产、触控容器、RTL 规则。

选择建议属于项目判断：例如需要精确感时可以比较 Outlined/Sharp，需要亲和感时可以比较 Rounded；最终必须放进真实页面和字体一起看，而不是按行业硬套。

同一套功能图标不应任意混用不同家族。填充与描边切换可以表达状态，并不等于换了图标家族。已有统一公司图标体系时优先复用，不为“每个项目不同”而刻意重画。

自定义功能图标可以使用，但需遵守清晰轮廓、统一比例、网格和光学修正等要求。Material 的基线是 24dp 网格、20dp 可视主体区域；可视图标不是触控目标。[自定义图标规范](https://m3.material.io/styles/icons/designing-icons)

还修正了一个过度限制：任意文字字符占位应禁止，但生产代码中正确配置、正常加载并有语义的官方图标字体并不是占位图标。Figma 交付仍优先可追踪的矢量组件。

## 5. 字体：不只选名字，要形成排版系统

Roboto 是默认选择，不是所有 Material 产品必须长得一样的要求。官方主题教程支持按品牌定制字体；字体页面也介绍了不同 Roboto 家族和 Noto 回退。[主题教程](https://developer.android.com/codelabs/m3-design-theming)、[字体指导](https://m3.material.io/styles/typography/fonts)

现在要求明确：

- 正文、表单、按钮等功能区域的阅读字体。
- 标题或内容展示时刻的表达字体；可以与正文相同。
- 中文与其他语言的实际字形覆盖和回退链。
- 字重、行高、字距、数字对齐、长文本换行。
- 字体文件、版本、授权、Figma 可用性和运行时可还原性。

不能只换英文字体就声称中文界面改好了。Roboto Flex 的拉丁字形变化不会自动应用到中文；需要实际比较中文与拉丁文字的大小、基线和视觉重量。

Material 官方允许 editorial treatments：用独立的文字表达形成内容重点，并与形状、色彩或动效结合。但要求一致、可复用，且不应把这些处理滥用于普通标签。[编辑式排版](https://m3.material.io/styles/typography/editorial-treatments)

因此，新的 Skill 不再把“任何字号必须等于基线表”当成绝对要求。普通 UI 仍按角色与可访问性设计，经过选择的展示字体和自定义尺寸则记录为可追溯 Token。

## 6. 对当前销售助手的建议方向

以下是待代表页面验证的建议，不是已经替你锁定的最终方案：

- 核心感觉：清晰、敏锐、有行动感，而非娱乐型的热闹。
- 让“下一步最重要的跟进”成为视觉中心，其余信息围绕任务组织。
- #D3FF5C 用于关键动作或重点提示，不把每个摘要区域都铺成荧光色。
- 客户资料使用清晰的行与分组；通话内容使用有节奏的时间线；避免全屏相同卡片。
- 用标题与业务数字的层级建立识别度，正文保持稳定可读。
- 图标先比较同一组 Outlined 与 Rounded 在实际页面中的效果，不同时混用。

主题种子本身没有“对比度合格/不合格”；应检查实际前景与背景组合。新流程已修正这一点，优先保留用户品牌色，通过语义角色和色调得到可用方案。

## 8. 下一次产品试用如何判断有效

不要看“文档多了多少页”，而要看：

- 代表页面是否让产品能明确说出喜欢/不喜欢的原因。
- 批量输出是否继承同一套视觉逻辑，而不是各页临时发挥。
- 交付后是否仍出现功能黑点、内容裁切和字体回退。
- 产品要求的返工轮次和交接不一致数量。

技术检查通过不代表设计有灵魂。下一次真实设计应以一张代表页先验证视觉方向；若方向仍像组件堆砌，应调整构图与内容表达，而不是继续加更长的合规清单。
